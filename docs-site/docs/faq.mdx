# 常见问题

## 报“未发现光驱”怎么办

`optiburn probe` 找不到设备时也会退出 0，这是刻意行为，方便脚本使用。先确认：

- 设备存在：`ls /dev/sr*`（Linux）或“此电脑”里有没有光驱盘符（Windows）。
- 权限足够：Linux 上把自己加入 `cdrom` 组，或临时用 root 验证一次。

## 提示命令找不到 xorriso

CLI 的默认刻录引擎（Linux）用 `xorriso`，Linux 上图形前端的盘上浏览与回读校验也用它。Debian/Ubuntu 用 `sudo apt install xorriso`。Windows 上没有可用的构建（MSYS2 的包编译时未链 libcdio，碰不到光驱），刻录请用原生引擎（图形前端默认，CLI 加 `--engine native`），读盘走原生解析（ADR-0018），都不需要外部工具。

## 写入被拒绝，提示盘被挂载

系统自动挂载了这张盘时不能写入。先卸载（Linux 上 `umount /dev/sr0`），再从界面或命令行重试。
界面会在对话框里给出提示。

## 可追加的盘，burn 被拒绝

已经有区段、还能继续写的盘要改用 `append`，命令行会直接提示。`burn` 面向新盘或已擦除的盘。

## 已封口的盘还能写吗

不能。已封口（finalized）的盘拒绝写入，需要换一张盘。写入时不要传 `--close-disc`
就能保留追加能力。

## Windows 上写的 UDF 盘能继续追加吗

不能。可追加盘的末区段不是 ISO 9660 时，写入会被拒绝，避免原有文件被遮蔽。这是刻意
行为，细节见[介质与文件系统](./compatibility)。盘上的内容本身可以浏览与复制：Windows
上原生读侧认 UDF（ADR-0021），设备页与“复制选中文件”之外的读盘能力都能用。

## DVD-RAM 和 BD-RE 上为什么行为不同

随机可写介质（DVD-RAM、BD-RE）不走多区段模型，xorriso 保持盘可覆写，`append` 的
多区段逻辑对它们不生效。Windows 上原生增长直接拒绝这类介质（报“可覆写介质上的追加
暂不支持原生引擎”）：这类盘用“刻录”整体重写即可，不必嫁接。

## 刻录中断了，数据还能救吗

按下面顺序走，顺序不能反：

1. 先别再写这张盘。不要跑 `repair`，不要继续追加，也不要在系统里格式化。要救的数据就在盘上，任何写命令都可能把它的入口改掉。
2. 跑一次抢救：`optiburn salvage --device D: --dest C:\rescued`（Linux 换成设备路径）。这一步只读盘面，把未关闭轨道（那次没关上的写入）里能读的部分按盘上路径抽到目标目录，并逐条报出完整、半截、一个字节都没写各多少。命令行与图形前端设备页（“抢救中断写入的数据”）走的是同一个引擎函数。
3. 读输出的两类细节。半截的 `.zip` 会被重建成只含完整条目的可解压缩包，报告会说明保留了多少条、从哪一条起没有保留（中断点落在第一条里面，或条目数总长超出普通 zip 的表达范围时，文件按原始字节保留）。标“一个字节都没写”的文件只存在于这次中断的会话里，同名文件若在更早的已关闭区段里，用普通读盘取出来更完整。
4. 抢救产物要核对再用。完整的文件按字节数与原文件对一遍，有原始副本时再对校验和。半截的按格式自检，zip 用解压工具打开验证。
5. 数据确认到手，再决定这张盘怎么办。`optiburn repair --device D:` 会关掉损坏的轨道与区段，盘可以继续写，但未关闭轨道这个入口随之消失，所以抢救必须在修复之前做。
6. 如果抢救报“盘上没有未关闭轨道”，说明中断的形态是另一种：固件已经把残片登记成了末区段。那种盘读盘时会自动回退到最新的可用区段（能看到更早的文件），追加时要求确认是否跳过残片，细节见 ADR-0022。

抢救目前只有原生读侧有：Windows 上直接可用，Linux 上会明确拒绝（xorriso 只认 TOC 里登记过的区段，未关闭轨道不在其中），理由与实测记在 ADR-0022 补记里。完整的实测样例（边界、文件归类、半截 zip 的处置）见[命令行用法](./usage)的 salvage 一节。

## Windows 上能用吗

已验证：构建、设备枚举与写盘（2026-10-10 在 Windows 的 USB 光驱与一张 CD-R 上写入并读回对拍，见 ADR-0017），读盘（同日同机验证：末区段读卷标、列目录树、抽取并与镜像逐文件对拍，xorriso 写的旧区段按绝对地址约定也读通，见 ADR-0018），以及追加（原生增长模式，见 ADR-0020）。Linux 侧的写盘路径有完整测试与真实介质验证。

## 盘上中文名在 Windows 上乱码

先确认用了 `dvd` 或 `bd` 这类带 Joliet 的 profile（`cd` 也带）。若仍有问题，把镜像文件
留在本地，用 `xorriso -indev` 核对一遍命名空间，再报告问题。
