# 命令行用法

二进制名是 `optiburn`。四个子命令各管一段流水线。

## build-image

把目录做成镜像。

```bash
$ optiburn build-image docs -o docs.iso --profile dvd --volume-id OPTIBURN
镜像: docs.iso
  扇区: 682
  字节: 1396736
  文件系统: ISO 9660, Joliet Level 3, UDF 1.02
```

| 参数 | 说明 |
|---|---|
| `-o, --output` | 输出路径。缺省时写到当前目录，文件名是 `<源目录名>.iso` |
| `--profile` | `cd`、`dvd`（默认）或 `bd`，决定写哪些文件系统 |
| `--volume-id` | 卷标 |

三个 profile 都保留 ISO 9660 主命名空间并写 Joliet（Windows 长文件名与中文名），
dvd 与 bd 还写对应版本的 UDF。文件数据区只有一份，不占双倍空间。

## burn

把镜像写到盘。

```bash
optiburn burn docs.iso --device /dev/sr0 --speed 8
```

| 参数 | 说明 |
|---|---|
| `--device` | Linux 是 `/dev/sr*`，Windows 是盘符（`E:`） |
| `--speed` | 倍速，留空交给驱动自选 |
| `--close-disc` | 写完后封盘。不传时盘保持可追加 |
| `--engine` | `xorriso`（默认值，需要 `PATH` 上有 `xorriso`）或 `native`（自己发 MMC 命令，Windows 上唯一可用），其它值报“未实现” |

默认多区段：盘写完后还能继续追加，省着用一张盘。需要归档一次性写死的场景就传 `--close-disc`。

## append

把目录内容追加为新区段。旧文件保持可见，Windows 挂载最后一个区段就能看到全部文件。

```bash
optiburn append photos --device /dev/sr0 --volume-id PHOTOS
```

- 空盘上这等价于首刻。
- `--close-disc` 在提交后封盘。
- 对随机可写介质（DVD-RAM、BD-RE）不生效，xorriso 保持盘可覆写。
- Windows 上走原生增长模式（ADR-0020）：新区段是 ISO 9660 加 Joliet，旧文件的数据块
  原地引用。资源管理器要弹出光盘再放回才会刷新挂载视图。

## probe

查看光驱。

```bash
$ optiburn probe
未发现光驱                      # 没有光驱（退出码 0）
# 有光驱时每个设备一行：
# /dev/sr0 | ASUS BW-16D1HT 3.10 | 空盘，1 个区段
```

没有光驱时也退出 0，可以放心放进脚本或 CI。

## 写盘前置检查

`burn` 与 `append` 在真正写入前会做几项检查，失败时给出中文原因与下一步：

- 盘片就绪：等盘片就绪，20 秒内每 500 ms 重试。
- 介质状态：已封口的盘拒绝写入。可追加盘提示改用 `append`。随机可写介质直接放行。
- 挂载占用：盘被系统挂载时拒绝写入，并提示先卸载。
- 末区段格式：可追加盘的末区段不是 ISO 9660（例如 Windows 写的 UDF 盘）时拒绝续写，
  避免原有文件被遮蔽。

检查全部通过后才会调用写盘引擎。

## salvage

抢救被中断的刻录：那次写入停在中途，轨道与区段没关上，数据还在盘上，但未关闭轨道不在盘
的 TOC 里，标准读取器（含 xorriso）看不见它。`salvage` 直接读裸盘上的字节，把它拿出来。

```bash
$ optiburn salvage --device D: --dest C:\rescued
未关闭轨道起点 301170，已经写下去的边界 310423（9253 块，约 18.1 MB）。
目录树里有 26 个文件：完整 25，半截 1，一个字节都没写 0。
抢救目录：C:/rescued
  [完整] /ARCHITECTURE.md（8.2 KB）
  [半截] /Atlas-v0.5.0-InstallFiles.zip（能读 18.0 MB，原大小 45.7 MB）
        中断点落在第一条「Atlas Playbook v0.5.0.apbx」里面，没有可保留的完整 zip 条目，文件按原始字节保留。
  …（其余文件同列）
```

- 写入边界由驱动器给出：读得出来的块就是写下去了。半截的文件按能读到的字节抽出来，
  起点在边界之后的文件标成“一个字节都没写”，一个都不往本地写。
- 半截的 `.zip` 只保留完整条目（数据长度与描述符自洽，存储条目再核 CRC32，压缩条目
  只核长度），重建中央目录与 EOCD，
  重建后常规解压工具直接能打开。中断点落在第一条里面时没有完整条目可留，文件按原始
  字节保留，并报出是哪一条没写完。
- 不需要源文件：边界与条目完整性都由盘上结构自证，别的电脑刻坏、盘拿到本机也能救。
- 只读盘面，不写盘。数据要留在盘上可继续读的话不要跑 `repair`：`repair` 会把会话关掉，
  之后未关闭轨道这个入口就不存在了（那时按普通读盘取即可）。
- GUI 设备页在盘可追加时也给出同一入口（“抢救中断写入的数据”），选好目标目录后与写盘
  同占任务槽，结果随完成消息给出。
