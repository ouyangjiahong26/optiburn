# 介质与文件系统

目标读者是“用 optiburn 做盘、在 Windows 上打开”的人。本页说明每种介质写哪些文件系统、
为什么，以及多区段与中断之后的盘怎么处理。完整的实测记录见仓库里的
[`docs/WINDOWS-COMPAT.md`](https://github.com/ouyangjiahong26/optiburn/blob/main/docs/WINDOWS-COMPAT.md)。

## 介质 × 文件系统

| Profile | ISO 9660 | Joliet | UDF | 依据 |
|---|---|---|---|---|
| `cd` | Level 2 + 长文件名（ISO 9660:1999） | Level 3 | 不写 | Windows 从 XP 起原生读 Joliet。CD 容量小，UDF 收益有限 |
| `dvd`（默认） | Level 2 + 长文件名 | Level 3 | 1.02（UDF Bridge） | DVD-ROM 通用标准。Windows Vista+ 认 UDF 1.02 |
| `bd` | Level 2 + 长文件名 | Level 3 | 2.50 | 蓝光标准要求。BD 播放与读取设备普遍只认 2.50 及以上 |

三个 profile 都保留 ISO 9660 主命名空间：老系统（DOS、老式机顶盒、部分车载机）只能读
ISO 9660，丢了它盘就成废盘。Joliet 提供 Windows 的长文件名与中文名，UDF 提供现代读取
路径。`dvd` 档的 ISO 与 UDF 共享同一份文件数据区（UDF Bridge），不占双倍空间。

## 镜像里实际长什么样（实测）

`build-image --profile dvd` 产出的镜像，用字节偏移直接读出来：

| 扇区 | 内容 |
|---|---|
| 0 至 15 | 系统区（本版本全 0，El Torito 与混合启动未启用） |
| 16 | ISO 9660 主卷描述符（类型 1，`CD001`） |
| 17 | 补充卷描述符（类型 2，Joliet） |
| 18 | 补充卷描述符（类型 2，ISO 9660:1999 长文件名） |
| 19 | 卷描述符序列结束符（类型 255） |
| 20 至 22 | UDF 卷识别序列：`BEA01` / `NSR02` / `TEA01` |
| 256 | UDF Anchor Volume Descriptor Pointer |
| 其余 | 目录结构与文件数据 |

`NSR02` 表示 UDF 1.02，`NSR03` 表示 UDF 2.00 及以上。`--profile bd` 写的是 `NSR03`，
`--profile cd` 完全没有 UDF 那三个扇区。这些断言在测试里锁住了，防止以后换上游版本时
布局悄悄变掉。

:::note[上游文档的一处勘误]

上游 hadris-cd 的文档注释写“扇区 17 至 19 是 UDF 卷识别序列”，与实测不符：ISO 卷
描述符序列实际占 16 至 19，UDF 卷识别序列在 20 至 22。以实测为准。

:::

## 怎么验证盘在 Windows 上能读

1. 做镜像：

   ```bash
   optiburn build-image <目录> -o disc.iso --profile dvd
   ```

2. 用参考实现回读，确认能列出全部文件（含中文文件名）：

   ```bash
   xorriso -indev disc.iso -ls /
   ```

   仓库测试会自动做这件事，并逐字节比对内容。

3. 刻录到盘后，用图形界面的“校验盘片”或回读流程，把盘上内容与源逐文件对比。

4. 有条件的话把盘插到 Windows 机器上，从“文件资源管理器”确认文件名、中文名与目录结构。

第 1、2 步与布局断言在 Linux 上真实执行。第 4 步在 2026-10-10 用 USB 光驱与一张 CD-R
做过，走的是原生引擎。2026-10-22 的两张 DVD-R 在 Linux 主机上写入、封口并读回，`xorriso`
列出全部文件，抽回的 sha256 与源一致，没有单独做 Windows 资源管理器挂载复核。

## 多区段与追加

### 哪些介质能追加

| 介质 | 能否追加区段 | 说明 |
|---|---|---|
| CD-R / CD-RW | 可以 | 每次追加占用 lead-in/lead-out，实测约 15 MB |
| DVD+R / DVD+RW | 可以 | 结构上支持，DVD+R 上的追加还没有介质实测 |
| DVD-R / DVD-RW | 不可以 | 顺序记录写一次即挂起，做不出第二区段 |
| DVD-RAM | 可以（按 UDF 包写） | 行为像可移动磁盘 |
| BD-R / BD-RE | 可以 | SRM 与伪覆盖两种模式，原生追加未实测 |

表里说的是介质本身的能力。工具侧还有一层：原生增长拒绝随机可写介质，Linux 默认档因此
回退 xorriso，Windows 没有可回退的 xorriso。这条限制只针对追加。

### 追加时盘上发生什么

Windows 只挂载最后一个区段，所以往已有内容的盘上写必须用 `append`。它读出末区段的
Joliet 目录树，生成一个只含目录结构与新文件数据的新区段，旧文件的数据块原地引用。

两平台默认走原生增长。这个新区段是 ISO 9660 加 Joliet，不带 UDF 描述符，卷标取新区段
的值。追加后的盘在 Windows 上仍看得到全部文件。

资源管理器要弹出光盘再放回才会刷新挂载视图。

Linux 在驱动器报随机可写介质、Profile 不在支持名单或调用方指定倍速时，整条追加回退
xorriso 增长模式。旧区段形状不支持嫁接时（没有 Joliet、含启动记录、含多 extent 文件
等），追加会被拒绝并说明原因。

### 哪些盘不能续写

末区段不是 ISO 9660 的盘（例如 Windows 写入的纯 UDF 盘）不能按增长模式续写。追加 ISO
区段后，Windows 只看最后一个区段，原有文件会从资源管理器里消失。`append` 的门禁会
检测并拒绝这种盘，提示换空白盘重刻。盘上的内容本身可以浏览与复制，因为原生读侧能读
UDF，只是不能续写。

### 中断之后

刻录中断留下坏末区段时，先跑 `salvage` 把未关闭轨道里的数据抽出来，再决定是否跑
`repair`。顺序不能反：`repair` 会关掉损坏的轨道与区段，未关闭轨道这个入口随之消失。

固件把中断残片登记成末区段时，读盘会回退到最新的可用区段，追加时要求确认，因为被跳过
区段里的文件不再出现在可见目录里。完整处置顺序见[常见问题](./faq)的“刻录中断了，数据
还能救吗”。
