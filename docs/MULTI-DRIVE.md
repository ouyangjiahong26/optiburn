# 多设备写入

多设备写入指一次会话内把内容分别写到两台及以上驱动器：每台设备一个独立任务，同一设备互斥，不同设备并行（ADR-0025，issue #50）。

## 能并行的动作与不能的

- 刻录（burn）与追加（append）可以跨设备并行：D: 在刻录的同时 E: 可以追加，两台互不影响。
- 校验与抢救都是读盘任务，不与同一台设备上的写任务并行；它们与其它设备的任务可以同时跑。
- 同一台设备上任何两个任务互斥：第二个任务会被拒，界面把该设备标为“任务进行中”并禁用。
- 制作镜像（build）没有设备，全局单占：它进行中再发起一次制作会被拒。

## GUI 多设备写入

1. 进入刻录页或追加页，点“添加设备”加一行：每行配一台设备与一份内容（刻录行选镜像，追加行选文件并核对卷标）。
2. 其它行已选的设备不会出现在本行下拉里；被正在跑的任务占用的设备出现在下拉里但禁用，标注“任务进行中”。
3. 倍速与封盘是页面级共享选项：一次批量按同一设置写入。损坏末区段的回退选项在追加页的行内，因为它属于那张盘的盘面状态。
4. 提交按行顺序逐行发起：设备与内容齐全的行都算数；某一台被拒（例如占用或门禁失败）只影响那一行，错误显示在该行内，已发起的行照常写入。
5. 内容区顶部的“当前任务”清单逐台显示进度，每条可单独“停止”；一台失败或被停不影响其它台。
6. 每行可单独“校验盘片”：该行设备被占用时按钮禁用。

## CLI 示例

跨进程本来就互不牵连，两个终端各写一台：

```
optiburn append --device D: --volume-id PHOTOS -g D:\photos
optiburn append --device E: --volume-id DOCS -g D:\docs
```

刻录同理，两个 `optiburn burn` 进程各带自己的 `--device` 与镜像。镜像输出路径（`build-image` 的 `-o`）不能相同：两个进程写同一个文件会互相破坏。只读共享同一份镜像（两个 `burn` 读同一个 `-i` 文件）是安全的。

## 同一个驱动器不要同时被 GUI 与 CLI 选中

GUI 的按设备任务槽只管自己进程内的互斥，与 CLI 进程之间没有跨进程设备锁（ADR-0025 的决策）。同一台光驱被 GUI 与 CLI 同时写入时，两股命令流会在驱动器上交错，轻则一方报错，重则写坏盘。多设备写入时每台设备只从一个入口发起。

## 实测数据

2026-10-16 本机两台 USB 光驱并发 `optiburn append`（各写一台，同一入口两个进程）：

- D: 用时 20.1 秒，区段数从 2 增到 3。
- E: 用时 37.0 秒，区段数从 8 增到 9。
- 两个进程都返回 0，读回清单完整。

## USB 布线建议

两台光驱同为 MediaTek 桥接（`VID_0E8D&PID_1887`），直连同一 root hub 的 5、6 口，协商速度都是 USB 2.0 High Speed 480 Mbps，共享一条链路。实测共享链路可正常并发（见上节数据）。介意耗时可把两台分接两路 xHCI（例如分别接前置与后置接口），各占一条链路。
