# ADR-0010：挂载门禁、卷标沿用与回读校验

- 状态：已接受
- 日期：2026-10-09

## 背景

实机使用暴露三个缺口。

桌面在插盘后自动挂载。此时写盘会失败，而前置检查（等就绪、读盘片信息）都能通过，
因为这两步只走只读的 SG_IO，不受挂载影响。失败发生在引擎侧：libburn 拿不到独占
设备，只回一句英文的设备占用报错。

GUI 追加页的卷标默认值是 OPTIBURN。不改它，新区段就会把盘上现有卷标静默改掉。

写完盘后没有任何回读校验入口。Linux 桌面挂载还看不到后续区段（内核块设备容量停在
第一区段，实测），用户检查刻录结果时更容易误判。

## 决策

1. 挂载检测放进 `optiburn-transport::mounted_at`。Linux 解析
   `/proc/self/mountinfo`，按设备的 major:minor 匹配，不依赖挂载来源怎么写
   （`/dev/sr0`、`/dev/cdrom`、udev 符号链接都能命中），挂载点里的八进制转义
   （`\040` 等）解析时还原。Windows 返回 `None`，理由与后续补法写在代码注释里
   （枚举已落地但没有真机验证，ADR-0005）。CLI 的 `ensure_burnable` 与 GUI 的
   `check_write_gates` 在动设备前检查（追加在暂存之前），`run_verify` 在抽取前
   单独检查，中文文案给出卸载命令。同一处还
   加了第二道门禁：追加路径上可追加盘的末区段必须是 ISO 9660，否则拒绝。实测
   Windows 写入的 UDF 盘（多区段 DVD-R）走 xorriso 时会被兜底当空白盘，续写
   ISO 区段后 Windows 只看到新内容，原有文件从视野里消失，与 ADR-0006 防的是
   同一类遮蔽事故。
2. 卷标沿用由 `optiburn-engine::read_volume_id` 实现：走
   `xorriso -indev <设备> -pvd_info`，解析 stdout 的 `Volume Id    : <文本>` 一行。
   GUI 追加页在选中设备后与点“刷新”时用它预填卷标，读不到就保持默认值。解析固定
   `LC_ALL=C` 让消息语言稳定，本机实测该 locale 下中文卷标原样输出。已知限制：盘
   被挂载时 xorriso 独占打开失败，预填失效，先卸载即可恢复。盘上没有可读的
   ISO 9660 结构时（实测 UDF 盘）xorriso 会兜底造空镜像并报默认卷标 `ISOIMAGE`，
   实现按 stderr 的 `Creating blank image` 拒绝，不把假卷标预填进界面。
3. 回读校验（GUI 的“校验盘片”）先把盘上最后一区段的目录树抽到临时目录
   （`optiburn-engine::extract_tree`，`xorriso -indev <源> -osirrox on -extract / <目标>`），
   再与源对比：追加模式把待刻录文件重新暂存成目录，刻录模式先把镜像树也抽出来对比。对比器
   `optiburn-engine::compare_trees` 是纯本地实现，单向比较，源里每个条目都要在盘上
   存在且内容一致，盘上多出的文件（多区段盘上的旧文件）不算差异。比较只认目录
   结构、文件名与内容字节，符号链接跳过，差异输出中文描述。校验是只读任务，占
   GUI 任务槽（`JobKind::Verify`），不提供中止。

   为什么不用 xorriso 自带的 `-compare_r`：本机实测（1.5.6）它的差异行与结论行都
   只出在 stdout，退出码恒为 0，不可依赖。更要紧的是它会比较 st_mtime、st_ctime 与
   st_mode，而原生写入（`grow`）默认带 Rock Ridge，时间戳进了会话，抽取回本地的
   文件 ctime 必然是新值，抽取树对比必出假阳性（实测）。内容一致才是刻录验收真正
   要的承诺，时间戳与权限不进承诺范围，Windows 端本就不读它们。

## 后果

- 实测结论留在本文件、`docs/WINDOWS-COMPAT.md` 与实现注释：`-compare_r` 会因时间戳
  与权限产生假阳性（原因见上）、挂载期间 libburn 报 `Cannot open busy device`、内核
  块设备容量停在第一区段、`LC_ALL=C` 下中文路径与卷标原样输出。
- 挂载检测只拦写盘与校验抽取（都需要独占或长时间占用设备），设备页浏览与复制走
  只读的 shared 打开，不受挂载影响。
- CLI 只接写前门禁（挂载与末区段检查）。卷标沿用与回读校验只在 GUI，CLI 参数本就
  显式，暂不加子命令。
- 校验要把盘上树抽到临时目录，本机 CD 读取约 5 倍速，百兆级内容约一分钟，期间没有
  百分比进度，界面按不确定进度显示。
- 盘片容量数字不显示：多区段盘的挂载视图只反映首区段，数字会误导，`READ CAPACITY`
  未在 v0 实现，界面以区段数与末区段文件清单（逐文件大小与所选合计）表达内容规模。
- 已知边界：盘上存在未完成区段时，第一次追加只做修复、不写内容却报告成功，实际
  内容要再写一次才落盘（实测）。
- 末区段 ISO 9660 检查只覆盖可追加（Appendable）盘。随机可写介质（Other，如
  DVD-RAM、BD-RE）上的旧内容同样可能被新写区段遮蔽，v0 未检查，等有真机再定。
- Windows 侧三条都未实现或未验证，等有真机再补（枚举已落地，ADR-0005）。
