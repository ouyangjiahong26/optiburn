# ADR-0003：先产镜像文件，再写盘

- 状态：已接受
- 日期：2026-10-05

## 背景

常规刻录工具有两条路：

1. **边生成边写盘**（管道式）：文件系统结构算出来直接往光驱写，不落中间文件；
2. **先产 `.iso` 再写盘**：两步分离，中间产物是普通文件。

## 决策

强制两段式：`build-image` 产出镜像文件，`burn` 把镜像写到盘上。CLI 不提供
「目录直接进光驱」的合并命令；`BurnJob` 的输入永远是镜像路径。

## 后果

- **可验证**：镜像字节在四个平台上一致，没有光驱也能把文件系统那条链路测完
  （`cargo test -p optiburn-mastering` 用 xorriso 回读对拍就是这条决策的直接产物）。
  管道式做不到这一点——没有盘就没法走到「文件系统写完了」那一步。
- **可归档、可复现**：镜像能存下来、校验和能公布、同一镜像可以刻多张盘；写盘失败
  （介质坏、断电、驱动器报错）只需重写，不必重新组织文件系统。
- **可分离排错**：报错时能立刻区分是「镜像错了」还是「写盘错了」。
- 代价：需要镜像大小的临时磁盘空间，并多一次磁盘读取。DVD 双层的 8.5 GB 镜像对本
  机的临时空间有要求；这是已知且可接受的取舍。
- 约束：CLI 的 `burn` 因此不接受目录参数，避免有人以为它会隐式先生成镜像。

## 被否决的方案

- **管道式（边生成边写）**：省一次磁盘 I/O，但把「文件系统是否正确」与「驱动器是否
  工作正常」两类失败揉成一团，且彻底失去无光驱测试的可能。本机与 CI 都没有光驱，
  这个代价无法接受。
- **两条路径都留**（既接受目录也接受镜像）：两个入口要维护两套错误处理与进度语义，
  v0 不需要。
