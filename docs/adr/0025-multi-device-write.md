# ADR-0025：多设备写入与按设备任务槽

- 状态：已接受
- 日期：2026-10-16

## 背景

GUI 的任务状态是全局单槽（`JobState(Mutex<Option<RunningJob>>)`）：任何时刻只允许一个阻塞任务，任何一台在写都拦住另一台发起（issue #50）。多驱用户一次只能写一张盘，第二台光驱闲置。issue 要求 GUI 支持一次向多台光驱写不同内容，并明确 CLI 侧不加跨进程设备锁。

## 决策

1. 任务槽从全局单槽改为按设备键控的映射：槽键即设备串（`E:`、`/dev/sr0`，与 `BurnJob::device`、`GrowJob::device`、CLI `--device` 同口径）。同一设备上的第二个任务被拒（`BusySlot`），不同设备并行。收尾按序号配对：事件载荷带 `device` 与 `seq`，旧任务的迟到收尾不清接棒的新任务。
2. 镜像制作（build）没有设备，用固定伪键 `"build"` 占一个槽（Windows 设备串是盘符加冒号、Linux 是 `/dev/*`，不会撞上这个词）。build 的并发不在本 issue 范围（Out of Scope 第 6 条），保持单占。
3. 不加跨进程设备锁：CLI 与 GUI 之间、多个 CLI 进程之间没有互斥，成本（锁文件、陈锁清理、崩溃残留）超过收益，风险由 `docs/MULTI-DRIVE.md` 的操作说明承担（同一台设备只从一个入口发起）。

## 后果

- 前端刻录页与追加页改成设备与内容配对表，逐行提交；被拒的行错误落在行内，不影响已发起的行。跨页面的“当前任务”清单按设备逐条显示进度与停止按钮，取消按设备下发。同一设备互斥由后端 `BusySlot` 兜底（双提交第二次被拒并显示在该行）。
- 关窗守卫改为“槽非空即拦”，确认退出时对全部任务置位取消并逐个等待收尾。
- 事件载荷 `job-progress` 与 `job-done` 增加 `device`、`seq` 字段。前后端同批发布，不留兼容形态。
- 实测（2026-10-16，两台 USB 光驱并发 `optiburn append`，各写一台）：D: 用时 20.1 秒区段数从 2 增到 3，E: 用时 37.0 秒区段数从 8 增到 9，两进程都返回 0，读回清单完整。两台同为 MediaTek 桥接，共享一条 USB 2.0 High Speed 链路，并发正常；分接两路 xHCI 可缩短耗时（详见 `docs/MULTI-DRIVE.md`）。

## 被否决的方案

- 多 GUI 实例（一窗一台设备）：与单实例插件冲突（重复启动只会把已有主窗口带到前台），且仍然需要跨进程设备锁。
- 全局取消（一台失败停全部）：一台的故障牵连其它台正在写的盘，把可完成的批次变成一批废盘。
- 全局唯一槽改成按任务类型键控：会让“校验”与“写盘”在同一台设备上并行，校验读到写了一半的盘。
