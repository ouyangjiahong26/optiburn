# ADR-0017：盘片容量读取与写前容量门禁

- 状态：已接受
- 日期：2026-10-10

## 背景

ADR-0010 决定不显示盘片容量：当时 `READ CAPACITY` 未实现，多区段盘的挂载视图只
反映首区段，数字会误导。此后实机使用暴露了真正的缺口：追加刻录前不知道盘上还剩
多少容量，放不下的数据要等 xorriso 写到一半失败才知道，废一张盘。刻录镜像同样
没有这道检查（路线图 v0.6 本就规划了写盘前拒绝放不下的镜像）。

## 决策

1. 容量来源是 `READ FORMAT CAPACITIES`（`optiburn-mmc` 的 `read_format_capacities`，
   op 0x23）。一条命令的响应里描述符类型 0 给介质最大容量、类型 1 给已写入量，
   差值即可用容量。数字来自盘片查询而不是挂载视图，推翻 ADR-0010“容量数字不
   显示”的决定，多区段误导的旧顾虑不复存在。
   `total` 与 `used` 两个口径要凑齐才显示、才参与门禁：实机观察到 CD-R 驱动器
   会把已写块数填进类型 0 描述符（见下面实测），单一口径的数字不可信。
2. 追加的待写入量用 `optiburn-engine::grow_print_size` 预演：与 `grow` 完全相同
   的参数表（`grow_base_args` 同源），把 `-commit` 换成 `-print_size`，xorriso
   自己算 ISO 9660/Joliet/UDF 的目录开销与合并盘上旧目录的增量。不采用源目录
   文件大小求和：小文件多的目录里，每文件半扇区取整加三份目录结构会让求和显著
   低估。刻录镜像的待写入量就是镜像文件大小。
   实测（xorriso 1.5.6）：关键行在 stdout，形态 `Image size   : 288s`（冒号前有
   对齐空格，数值尾部 `s`，单位 2048 字节块）；数值只含即将提交的新区段，盘上
   已有区段不在内，与可用容量同口径。`-print_size` 必须有输出目标；对一次性
   介质不写入（写入只发生在 `-commit`），可覆写介质（含 xorriso 的 stdio 文件
   目标）在退出时自动提交未写修改，那是目标介质的行为，与 `-print_size` 无关
   （对照实验证实）。
3. 门禁条件是“待写入 + `SESSION_OVERHEAD` ≤ 可用容量”，余量 16 MB 收在
   `optiburn-engine`，CLI 与 GUI 共用。`-print_size` 与镜像大小都只算数据区，
   不含区段 lead-in/lead-out 与链接区：CD 每区段最大约 15 MB，DVD/BD 约 2 MB，
   16 MB 覆盖最坏情形。余量不够的极端情形由 xorriso 写入失败兜底。
   CLI 的 `ensure_fits` 与 GUI 的同名门禁（`run_disc_task` 里）都遵守同一条：
   读不到容量口径就打印提示后放行。门禁是尽力而为的预检，不该成为新的故障点。
   GUI 追加的检查点在暂存之后（`GrowJob.src` 是暂存目录），镜像刻录的检查点在
   跑引擎之前；拒绝时 GUI 报 `capacity` gate，弹引导对话框。

## 实机验证（HL-DT-ST DVDRAM GP70N，CD-R 80 分钟，4 个 ISO 区段 + 1 个区段）

验证后设备被移除，以下数字是当时抓到的一次性证据：

- `READ FORMAT CAPACITIES` 对 28 字节请求只回 12 字节并计 16 字节 residual。
  变长响应不能按满长判定，`read_format_capacities` 按 residual 截断后解析，
  有效区间再由头部列表长度圈定。
- 响应里只有一个描述符：类型位 0，但数值 257820 块与盘总容量 359847 块
  （xorriso 读出）对不上、恰等于已写块数。CD 家族介质没有格式化容量语义，
  驱动器把已写口径填进了类型 0。凑齐双口径才显示的规则因此挡住了怪癖数据。
- xorriso 对同一张盘读出 readable 257820、writable 95127、overall 359847、
  NWA 264720，是本 ADR 数字的对照基准。
- CD-R 的总容量在 ATIP（`READ TOC/PMA/ATIP` format 2）里。实测该命令 format
  字段的两种 MMC 写法（byte 9 高 2 位、byte 6 低 2 位）在这台驱动器上都返回
  TOC 样数据（未生效），libburn 用的 byte 9 低 2 位写法未及验证（设备移除）。

## 后果

- probe（CLI 行尾“总容量 X，可用 Y”）、GUI 设备页卡片与追加页设备行都显示容量；
  读不到口径（CD 介质典型）时整段省略，CLI 刻录路径打印“跳过容量检查”提示。
- CD-R/RW 读不到容量口径时没有容量展示与门禁保护，这是已知边界；补齐要等
  ATIP 读取（format 字段布局先在有真机时定稿）。BD/DVD 一次性介质按规范实现，
  解析由固定缓冲区单测覆盖，真机验证待有盘时复验。
- 追加多一次 xorriso 预演进程：读盘上目录树加遍历源目录，秒级开销，刻录安全
  换来的代价可接受。
- Windows 侧 `read_format_capacities` 与门禁随代码落地，SPTI 不回 residual
  （恒 0），变长截断逻辑在那里不生效，解析按列表长度圈边界仍然安全。
