# ADR-0011：GUI 追加改为多选文件加剪贴板粘贴

- 状态：已接受
- 日期：2026-10-09

## 背景

实机试用反馈两点。第一，最常用的操作是把单个或多个文件刻到盘上（空盘或有内容的
盘），界面里找不到入口：旧设计只接受一个目录，要求先建文件夹再选，不符合使用习惯。
第二，用户明确期望两种添加方式：打开文件管理器多选文件，或在文件管理器复制文件后
回到本页按 Ctrl+V 粘贴。

## 决策

1. 追加页改为“待刻录文件”列表。添加方式有三种：系统文件选择框多选、列表内单个
   移除或整体清空、页面内 Ctrl+V 或“粘贴”按钮。粘贴由界面拦截按键、经 GTK 读
   系统剪贴板完成。不能只依赖 WebKit 的 paste 事件：焦点不在可编辑控件上时它不
   派发（实测无响应）。读取优先标准目标 `text/uri-list`，兜底解析
   `x-special/gnome-copied-files`。焦点在可编辑控件里时不拦截按键，让文本正常粘贴。
2. 写入语义：所选文件复制进临时暂存目录（同名文件报错而不是覆盖），增长模式把
   暂存目录作为盘根写入，任务结束（含失败）即删暂存目录。文件在盘根平铺。
3. 回读校验对文件方案重新暂存一次再与盘上内容对比，不留跨任务的暂存状态。
4. GUI 不再提供目录作为追加输入，CLI 的 `optiburn append <目录>` 保留。

## 被否决的方案

- 维持只选目录：用户已明确否定。
- 由前端复制文件到暂存（tauri fs 插件）：要新增插件与权限面，复制逻辑分成两处。
- 用硬链接代替复制：跨文件系统不可用，且源文件后续变化会改变盘上内容的来源。
- 暂存目录留到校验复用：跨任务的生命周期与清理更复杂，重新暂存更简单。

## 后果

- 暂存需要与所选文件总大小等量的临时空间，位置在系统临时目录。
- 粘贴链路依赖 WebKitGTK 的剪贴板行为，实测范围是 Linux 桌面，Windows 待真机验证。
- 校验对比的是校验时刻的本地文件与盘上内容，与目录方案语义一致。
