# ADR-0033：READ TRACK INFORMATION 的双形态探测与响应轨道号校验

- 状态：已接受
- 日期：2026-10-28

## 背景

issue #75：图形前端追加页对一张健康的可追加 DVD-R（HL-DT-ST DVDRAM GP70N，
CMC DVD-R 顺序记录，4 个已完结区段加隐形轨道 5）报“驱动器没有报出可写地址
（NWA_V 清零，末区段起点 118512）”，而 xorriso（内置 libburn）对同一张盘报
`Media nwa: 457040s`、可写 1840848 块，全部区段可读。盘与驱动器都健康。

门禁链路复现：`read_writable_track_information` 先问轨道 0xFF，两种 CDB 形态都被拒
（ASC 0x24 与 0x21）；回退问 READ DISC INFORMATION 字节 6 的末条轨道号 5，驱动器
返回的却是已关闭轨道 4 的描述符（轨道号 4、起点 118512、NWA_V 清零、NWA 与剩余
块数均 0）。已关闭轨道本来就没有可写地址，门禁把“问错轨道”误判成“盘上地址不可信”。
probe 的总容量 923.4 MB（实为已写范围）是同一根因在容量探测上的症状。

## 证据

同一张盘、同一轨道号 5，只换 READ TRACK INFORMATION（0x52）的 CDB 形态
（2026-10-28 实测，xorriso `-scsi_log` 与本仓库传输层的原始下发对拍一致）：

| 形态 | CDB 骨架 | GP70N 加可追加 DVD-R 的回答 |
|---|---|---|
| 标准（libburn 同款） | `52 01`，轨道号 32 位大端放字节 2-5 | 隐形轨道 5 的真实描述符：NWA_V 置位、起点与 NWA 均 457040、剩余 1840848 块 |
| 兼容（当时的现行形态） | `52 00`，轨道号 16 位放字节 2-3 | 轨道 4 的描述符（答非所问，不报错） |
| 字节 1 置 0 加 32 位轨道号 | `52 00`，轨道号放字节 2-5 | 轨道 1 的描述符（答非所问，不报错） |
| 字节 1 置 1 加 16 位轨道号 | `52 01`，轨道号放字节 2-3 | ILLEGAL REQUEST（ASC 0x24） |
| 0xFF（两种形态） | 同上 | ILLEGAL REQUEST（ASC 0x24 与 0x21） |

另一台（或同一台换 CD-R 介质，2026-10-11 实测，ADR-0031 前身）：轨道号放 32 位或
字节 1 置 1 的组合分别回地址全零的退化描述符与 INVALID FIELD IN CDB，只有
“字节 1 置 0、轨道号 16 位放字节 2-3”能取回真实描述符。当时的修复把这一种形态定为
唯一写法，没有重验其它介质。

结论：驱动器对这条命令的字段解释没有一致实现，且错答是静默的（命令成功、字段合法、
地址全错），只有比对响应里的轨道号才能发现。

## 决策

1. `track_info_cdb` 改为标准形态：字节 1 置 1，轨道号 32 位大端放字节 2-5
   （libburn 的 `mmc_read_track_info` 同款，MMC-5 的 Logical Track Number 字段）。
   原 16 位形态保留为 `track_info_cdb_compat`，只在标准形态不可用时使用。
2. `MmcDevice::read_track_information` 做双形态探测：先标准形态；仅当它被
   ILLEGAL REQUEST 拒绝（这个形态在这台驱动器上没定义）或答非所问
   （`MmcError::TrackMismatch`）时，退回兼容形态再问一次；两种形态都失败时回标准
   形态的错误。真实传输故障不换形态重问，原样上抛。
3. 响应轨道号校验：`TrackInfo` 增加 `number`（响应字节 2），问具体轨道号时必须与
   询问值相等，否则按 `TrackMismatch`（问的与答的轨道号都带在错误里）处理。0xFF
   查询按定义回真实轨道号，无法比对，跳过校验。
4. 实测响应字节进固定缓冲区测试：隐形轨道 5 与已关闭轨道 4 两组（write.rs），
   外加 GP70N DVD-R 全链路回归（mmc 层，0xFF 两种形态被拒、末条轨道号 5 走标准
   形态成功、兼容形态的错答被校验挡住）。

## 后果

- 门禁、镜像刻录起始块、修复、容量探测、salvage 全部经 `read_writable_track_information`
  受益，不需要各自改动。
- CD 只认兼容形态的驱动器保底：标准形态在那里被拒后自动换兼容形态，行为与
  2026-10-11 的实测一致（本次无 CD 介质可复测，靠形态回退保底）。
- 错答不再静默：两种形态都答非所问时，错误信息直接给出问的与答的轨道号。
- 已关闭轨道的“NWA_V 清零”响应仍在（它本身是正确答案），门禁对它的判定不变。

## 被否决的方案

- 只改标准形态、删掉兼容形态：2026-10-11 的 CD-R 实测里只有兼容形态可用，删除后
  CD 介质的轨道信息会拿不到。
- 校验放宽为“响应轨道号小于等于询问值也算对”：GP70N 的错答恰好是轨道号减一
  （问 5 答 4），放宽等于把病灶放行。
- 在门禁层（engine）做校验：错答发生在传输与解析之间，只有 mmc 层能看到原始轨道号，
  校验必须与双形态探测同层。
