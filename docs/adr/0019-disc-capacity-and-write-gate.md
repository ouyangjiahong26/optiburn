# ADR-0019：盘片容量读取与写前容量门禁

- 状态：已接受（决策 3 已由 2026-10-15 的修订取代，见文末“修订”一节）
- 日期：2026-10-10

## 背景

ADR-0010 决定不显示盘片容量：当时 `READ CAPACITY` 未实现，多区段盘的挂载视图只
反映首区段，数字会误导。此后实机使用暴露了真正的缺口：追加刻录前不知道盘上还剩
多少容量，放不下的数据要等 xorriso 写到一半失败才知道，废一张盘。刻录镜像同样
没有这道检查（路线图 v0.7 本就规划了写盘前拒绝放不下的镜像）。

## 决策

1. 容量口径分两个来源。可用容量取 `READ TRACK INFORMATION`（0x52）的剩余块数
   （`optiburn-mmc` 的 `TrackInfo::free_blocks`，响应字节 16-19）：顺序介质
   （CD-R/RW、DVD±R、BD-R）上“下一个可写地址加剩余块数”就是盘的可写上限，即
   总容量（libburn 的 `media_lba_limit` 同口径，实测 286770 加 73077 等于
   359847 块，与 xorriso 读出的整体容量一致）。轨道号先按 0xFF 问（MMC 只为 CD
   与 DVD+R 族定义它，实测的 CD-R 驱动器认），驱动器拒绝时改用 `READ DISC
   INFORMATION` 字节 6（末区段里最后一条轨道的编号，按 MMC 定义把 NWA 处的隐形
   轨道算在内，可追加盘上就是那条开放轨道，libburn 的 `mmc_read_track_info` 对
   DVD-R 族就是这么传的）再问一次，字段读不到（0x51 失败或为 0，空白盘就是这样）
   时按轨道 1 问一次，仍读不到才回落格式化容量。`READ FORMAT CAPACITIES`（0x23）只作退回口径：首条描述符字节 4 的低 2 位是描述符
   类型（1 未格式化介质、2 已格式化介质、3 无介质或容量未知），块数乘固定的 2048
   字节块长（字节 5–7 是类型相关参数，不是块长）。类型 1 的最大可格式化容量同时是
   总容量与可用容量（未格式化介质整盘待写），类型 2 的当前格式化容量只作总容量，
   不参与门禁（一次写介质上它是已写范围，不是剩余空间）。两条路都读不到时两个口径
   都不可知，跳过显示与门禁。
2. 追加的待写入量用 `optiburn-engine::grow_size` 预演。Linux 上是 xorriso 的预演：
   与 `grow` 完全相同的参数表（`grow_base_args` 同源），把 `-commit` 换成
   `-print_size`，xorriso 自己算 ISO 9660/Joliet/UDF 的目录开销与合并盘上旧目录的
   增量。不采用源目录文件大小求和：小文件多的目录里，每文件半扇区取整加三份目录
   结构会让求和显著低估。Windows 上由原生增长引擎按会话生成计划算尺寸（ADR-0020），
   同一条 `grow_size` 分派。刻录镜像的待写入量就是镜像文件大小。
   实测（xorriso 1.5.6）：关键行在 stdout，形态 `Image size   : 288s`（冒号前有
   对齐空格，数值尾部 `s`，单位 2048 字节块），数值只含即将提交的新区段，盘上
   已有区段不在内，与可用容量同口径。`-print_size` 必须有输出目标；对一次性
   介质不写入（写入只发生在 `-commit`），可覆写介质（含 xorriso 的 stdio 文件
   目标）在退出时自动提交未写修改，那是目标介质的行为，与 `-print_size` 无关
   （对照实验证实）。
3. 门禁条件是“待写入 + `SESSION_OVERHEAD` ≤ 可用容量”，余量 16 MB 收在
   `optiburn-engine`，CLI 与 GUI 共用。`-print_size` 与镜像大小都只算数据区，
   不含区段 lead-in/lead-out 与链接区：CD 每区段最大约 15 MB，DVD/BD 约 2 MB，
   16 MB 覆盖最坏情形。余量不够的极端情形由引擎写入失败兜底。
   （本条已由 2026-10-15 的修订取代：余量按动作与介质取值，优先用盘上实测几何，
   见文末。）
   可用容量读不到时放行（CLI 打印“跳过容量检查”提示，GUI 静默放行）：门禁是
   尽力而为的预检，不该成为新的故障点。GUI 追加的检查点在暂存之后
   （`GrowJob.src` 是暂存目录），镜像刻录的检查点在跑引擎之前；拒绝时 GUI 报
   `capacity` gate，弹引导对话框。

## 实机验证（HL-DT-ST DVDRAM GP70N，CD-R 80 分钟，8 个区段）

设备在验证时接在本机，下列数字是 2026-10-10 的读数：

- `READ TRACK INFORMATION`（轨道 0xFF）：起始 286770、NWA 286770、剩余 73077、
  轨道大小 73077。NWA 加剩余等于 359847 块，与 xorriso 读出的整体容量一致，
  剩余块数就是可用容量的正确来源。
- `READ FORMAT CAPACITIES` 对 28 字节请求回一条描述符，字节 4 = 0x02，即类型 2
  （已格式化介质），数值 279870 块是盘的已写范围。它不进可用容量口径，只在
  退回展示里用。
- 变长响应不能按满长判定：此前一次抓包里驱动器对 28 字节请求只回 12 字节并计
  16 字节 residual，解析按实际返回长度截断，有效区间再由头部列表长度圈定。
- CD-R 的总容量不必读 ATIP：剩余块数口径已经给出可写上限。ATIP（`READ TOC/PMA/
  ATIP` format 2）读取仍未实现，留给需要媒体出厂容量的场景。
- 可覆写介质（DVD+RW、DVD-RAM、BD-RE）的轨道信息按规范返回 NWA 0 与剩余 0，
  退回格式化容量口径，只显示总容量、跳过门禁，真放不下由引擎写入失败兜底。

## 后果

- probe（CLI 行尾“总容量 X，可用 Y”）、GUI 设备页卡片与追加页设备行都显示容量；
  读不到的口径整段省略，CLI 刻录路径打印“跳过容量检查”提示。
- 顺序介质的可用容量与总容量来自剩余块数口径。`READ TRACK INFORMATION` 的轨道号
  先按 0xFF 问（MMC 只为 CD 与 DVD+R 族定义它），被拒时改用 `READ DISC INFORMATION`
  字节 6 的末条轨道号（按 MMC 定义含 NWA 处的隐形轨道，也就是开放的那条）再问一次，
  字段读不到时按轨道 1 问，因此 DVD-R、DVD-RW 顺序、DVD-R DL、BD-R 上也能拿到剩余
  块数，不再静默跳过门禁。空白或可覆写介质按能读到的格式化容量显示，未格式化介质
  （类型 1）整盘待写，可直接参与门禁。末条轨道号取自 `READ DISC INFORMATION` 字节 6，
  本机盘上只核对过字节 5（可追加 CD-R 的隐形轨道），字节 6 的取值按标准走单测
  （0xFF 被拒、0x51 给出末轨号、第二次 0x52 成功，另有 0x51 读不到时按轨道 1 的
  边界分支），真机验证待有 DVD-R 或 BD-R 盘时复验。BD/DVD 一次性介质按标准实现，
  解析由固定缓冲区单测覆盖，真机验证待有盘时复验。
- 追加多一次 xorriso 预演进程：读盘上目录树加遍历源目录，秒级开销，刻录安全
  换来的代价可接受。
- Windows 侧 `read_disc_capacity` 与门禁随代码落地，SPTI 不回 residual（恒 0），
  READ FORMAT CAPACITIES 的变长截断在那里不生效，解析按列表长度圈边界仍然安全。

## 修订（2026-10-15）：区段开销按动作与介质取值，优先用盘上实测几何

决策 3 的 16 MB 常数被本节取代。起因是一次实机追加被拒：待写入 8.3 MB、可用容量
22.6 MB，两个数字并列看着像放得下，实际放不下，而常数本身没有实测依据（引入提交
`f5c24ff` 只写了“CD 每区段最大约 15 MB”，同一时期的 `WINDOWS-COMPAT.md` 写的是
“约 20 MB”，两处都不是读数）。

### 实测（HL-DT-ST DVDRAM GP70N，CD-R 80 分钟，盘上 10 个区段，2026-10-15）

量法是相邻区段起点之差减去上一区段的数据块数，数据块数取该区段 PVD 的卷空间大小
（PVD 在区段起点加 16 块，描述符字节 80-83 小端、84-87 大端）：

| 区段转换 | 差额（块） | 推断 |
|---|---|---|
| 1 到 2 | 11845 | 首会话导出区 6750 加下一会话 lead-in 加链接区 |
| 2 到 3、3 到 4、4 到 5 | 7341、7338、7315 | 后续会话导出区 2250 加 lead-in 加链接区 |
| 5 到 6 到 10（五次） | 7335、7336、7346、7316、7335 | 同上 |

读数由 `OPTIBURN_DEVICE=D: cargo test -p optiburn-engine -- --ignored inspect_session_gaps
--nocapture` 复现（只读），默认值就按这一档取。

同日另一张 CD-R 80 分钟（8 个区段、可追加）的读数，用来核对实测分支真的随介质变：
末个已完结区段起点 347692、写了 3486 块、下一个可写地址 358230，差额 7052 块
（14442496 字节），门禁据此算出 append 档 7052 块、close 档 2250 块，本机默认值 7335 块
没有被用上。该盘只剩 1617 块（3.2 MB），追加被拒，文案为“这张盘放不下本次写入：待写入
约 236.0 KB，区段开销（lead-in 与 lead-out）还要约 13.8 MB，盘上可用容量约 3.2 MB。
请减少待写内容或更换盘片。”，三个数字自洽，不再出现原先那种看着矛盾的并列。

封盘那次（第 10 区段）数据末到导出区起点只有 436 块，但这是地址账面值，不作物理
依据：导出区长度按 ECMA-394 §5.7.1，后续会话最少 2250 块、首会话最少 6750 块。

### 新口径

1. CD 保持可追加：余量取实测差额，读不到几何时用 7335 块，首区段（空盘）用 11845 块。
   两条路都再取标准下限兜底（非首区段 6750 块、首区段 11250 块，即 ECMA-394 的导出区
   下限加 libburn 的 4500 块 lead-in）。
2. CD 封盘：首区段 6750 块、后续区段 2250 块。封盘不必为下一区段留 lead-in，此前一并
   按 16 MB 拦，会把能写成的封盘追加误拒。同一张盘上可用 11547 块（22.6 MB）时写下过
   4536 块的封盘区段，按旧口径 4536 加 8192 等于 12728 块会被拒，按封盘档 2250 块则
   放行。
3. 非 CD（DVD±R、BD-R）：优先用实测差额，读不到时沿用 16 MB。DVD+R 的标准值有出处
   （非最终会话的 Intro 加 Closure 共 2048 扇区，封盘导出区最少 5120 扇区，ECMA-349
   §22 与 §20），封盘那一次按 5120 扇区的下限兜底，因为实测差额量到的是会话之间的
   转换，不含导出区。本机没有 DVD 与 BD 介质实测，BD-R 的 zone 尺寸也没有公开的标准
   值。另有一条限制：实测差额走 `READ TRACK INFORMATION` 的轨道 0xFF，而 MMC 只为 CD
   与 DVD+R 族定义它，DVD-R 与 BD-R 上取不到，回落 16 MB（这两种介质的原生写入路径
   同样依赖轨道 0xFF，ADR-0017 记了这条缺口）。
4. 实测差额的读法：READ TOC Format 1 取末区段起点，READ TRACK INFORMATION 轨道 0xFF
   取 NWA（要求 NWA_V 置位且 NWA 大于末区段起点），READ(10) 读末区段起点加 16 块，
   校验标准标识 `CD001` 与双端序两个半值相等，差额等于 NWA 减（末区段起点加卷空间
   大小）。任何一步读不到就走默认值，全程只用只读命令，不碰修复与写序列。
5. 门禁拒绝时把三个数字都写进文案（待写入、区段开销、可用容量），因为这次拒绝的
   困惑正是两个数字看着自相矛盾。

### 后果

- `SESSION_OVERHEAD` 删除，口径收在新的 `optiburn-engine::capacity`：调用方的写前
  门禁（CLI 与 GUI）与引擎内增长路径的门禁共用 `session_headroom` 与 `capacity_gate`，
  拒绝错误带 `headroom` 字段供文案使用。
- 那次被拒的写入复算：待写入 4250 块加实测开销 7335 块等于 11585 块，可用 11547 块，
  仍差 38 块（76 KB），保持可追加的追加继续拒绝但文案说明原因。同一份内容封盘写入
  放行（余量 2250 块）。差额在同批读数里落在 7315 到 7346 块之间。
- DVD 与 BD 的实测仍缺（空白 CD-R 的口径与三档余量已在真机核对，见下），有这些介质时
  按同一条读法补。

### 真机写入核对（2026-10-15，空白 CD-R 80 分钟）

同一台驱动器上换一张空白盘，用 `optiburn append`（Windows 原生增长路径）连写三个会话，
核对门禁算出的余量与写入后驱动器实际推进的地址是否对得上：

| 步骤 | 门禁用的余量（块） | 写入（块） | 复读的 NWA | 复读的实测差额（块） |
|---|---|---|---|---|
| 空白盘首区段，保持可追加 | 11845（无几何可量，取默认） | 1003 | 12405 | 11402 |
| 第二次追加，保持可追加 | 11402（实测） | 514 | 19821 | 6902 |
| 第三次追加，`--close-disc` 封盘 | 2250（封盘档） | 275 | 导出区起点 20121 | 25 |

三处地址都对得上：12405 等于 1003 加 11402，19821 等于 12405 加 514 加 6902，
导出区起点 20121 等于 19821 加 275 加 25。三次写入退出码都是 0，封盘后 `probe` 报
“已封口，3 个区段，总容量 39.3 MB”，与导出区起点口径一致（20121 块）。

空白盘的可用容量口径也一并实测：轨道 0xFF 报 nwa=0、剩余 359847 块（整盘），
门禁据此按首区段档放行。封盘档 2250 块的地址账面值在这张盘上是 25 块，物理导出区
长度不由此判定，仍按 ECMA-394 的下限取。

三张盘的首区段转换差额分别是 11845、11402、11402 块，后续区段转换是 6902 到 7346 块。
默认值取 11845（与最坏读数相同）与 7335（比最坏读数 7346 少 11 块），读不到几何时
与观测区间同一量级。
