# ADR-0019：盘片容量读取与写前容量门禁

- 状态：已接受
- 日期：2026-10-10

## 背景

ADR-0010 决定不显示盘片容量：当时 `READ CAPACITY` 未实现，多区段盘的挂载视图只
反映首区段，数字会误导。此后实机使用暴露了真正的缺口：追加刻录前不知道盘上还剩
多少容量，放不下的数据要等 xorriso 写到一半失败才知道，废一张盘。刻录镜像同样
没有这道检查（路线图 v0.7 本就规划了写盘前拒绝放不下的镜像）。

## 决策

1. 容量口径分两个来源。可用容量取 `READ TRACK INFORMATION`（0x52）的剩余块数
   （`optiburn-mmc` 的 `TrackInfo::free_blocks`，响应字节 16-19）：顺序介质
   （CD-R/RW、DVD±R、BD-R）上“下一个可写地址加剩余块数”就是盘的可写上限，即
   总容量（libburn 的 `media_lba_limit` 同口径，实测 286770 加 73077 等于
   359847 块，与 xorriso 读出的整体容量一致）。`READ FORMAT CAPACITIES`（0x23）
   只作退回口径：首条描述符字节 4 的低 2 位是描述符类型（1 未格式化介质、
   2 已格式化介质、3 无介质或容量未知），块数乘固定的 2048 字节块长（字节 5–7
   是类型相关参数，不是块长）。类型 1 的最大可格式化容量同时是总容量与可用容量
   （未格式化介质整盘待写），类型 2 的当前格式化容量只作总容量，不参与门禁
   （一次写介质上它是已写范围，不是剩余空间）。两条路都读不到时两个口径都不可知，
   跳过显示与门禁。
2. 追加的待写入量用 `optiburn-engine::grow_print_size` 预演：与 `grow` 完全相同
   的参数表（`grow_base_args` 同源），把 `-commit` 换成 `-print_size`，xorriso
   自己算 ISO 9660/Joliet/UDF 的目录开销与合并盘上旧目录的增量。不采用源目录
   文件大小求和：小文件多的目录里，每文件半扇区取整加三份目录结构会让求和显著
   低估。刻录镜像的待写入量就是镜像文件大小。
   实测（xorriso 1.5.6）：关键行在 stdout，形态 `Image size   : 288s`（冒号前有
   对齐空格，数值尾部 `s`，单位 2048 字节块），数值只含即将提交的新区段，盘上
   已有区段不在内，与可用容量同口径。`-print_size` 必须有输出目标；对一次性
   介质不写入（写入只发生在 `-commit`），可覆写介质（含 xorriso 的 stdio 文件
   目标）在退出时自动提交未写修改，那是目标介质的行为，与 `-print_size` 无关
   （对照实验证实）。
3. 门禁条件是“待写入 + `SESSION_OVERHEAD` ≤ 可用容量”，余量 16 MB 收在
   `optiburn-engine`，CLI 与 GUI 共用。`-print_size` 与镜像大小都只算数据区，
   不含区段 lead-in/lead-out 与链接区：CD 每区段最大约 15 MB，DVD/BD 约 2 MB，
   16 MB 覆盖最坏情形。余量不够的极端情形由引擎写入失败兜底。
   可用容量读不到时放行（CLI 打印“跳过容量检查”提示，GUI 静默放行）：门禁是
   尽力而为的预检，不该成为新的故障点。GUI 追加的检查点在暂存之后
   （`GrowJob.src` 是暂存目录），镜像刻录的检查点在跑引擎之前；拒绝时 GUI 报
   `capacity` gate，弹引导对话框。

## 实机验证（HL-DT-ST DVDRAM GP70N，CD-R 80 分钟，8 个区段）

设备在验证时接在本机，下列数字是 2026-10-10 的读数：

- `READ TRACK INFORMATION`（轨道 0xFF）：起始 286770、NWA 286770、剩余 73077、
  轨道大小 73077。NWA 加剩余等于 359847 块，与 xorriso 读出的整体容量一致，
  剩余块数就是可用容量的正确来源。
- `READ FORMAT CAPACITIES` 对 28 字节请求回一条描述符，字节 4 = 0x02，即类型 2
  （已格式化介质），数值 279870 块是盘的已写范围。它不进可用容量口径，只在
  退回展示里用。
- 变长响应不能按满长判定：此前一次抓包里驱动器对 28 字节请求只回 12 字节并计
  16 字节 residual，解析按实际返回长度截断，有效区间再由头部列表长度圈定。
- CD-R 的总容量不必读 ATIP：剩余块数口径已经给出可写上限。ATIP（`READ TOC/PMA/
  ATIP` format 2）读取仍未实现，留给需要媒体出厂容量的场景。
- 可覆写介质（DVD+RW、DVD-RAM、BD-RE）的轨道信息按规范返回 NWA 0 与剩余 0，
  退回格式化容量口径，只显示总容量、跳过门禁，真放不下由引擎写入失败兜底。

## 后果

- probe（CLI 行尾“总容量 X，可用 Y”）、GUI 设备页卡片与追加页设备行都显示容量；
  读不到的口径整段省略，CLI 刻录路径打印“跳过容量检查”提示。
- 顺序介质（CD-R/RW、DVD±R、BD-R）的可用容量与总容量都来自剩余块数口径。
  空白或可覆写介质按能读到的格式化容量显示，未格式化介质（类型 1）整盘待写，
  可直接参与门禁。BD/DVD 一次性介质按规范实现，解析由固定缓冲区单测覆盖，
  真机验证待有盘时复验。
- 追加多一次 xorriso 预演进程：读盘上目录树加遍历源目录，秒级开销，刻录安全
  换来的代价可接受。
- Windows 侧 `read_disc_capacity` 与门禁随代码落地，SPTI 不回 residual（恒 0），
  READ FORMAT CAPACITIES 的变长截断在那里不生效，解析按列表长度圈边界仍然安全。
