# ADR-0027：增长模式默认后端切到原生

- 状态：已接受
- 日期：2026-10-15

## 背景

ADR-0025 量清了默认档的代价：Linux 上一次追加的写前窗口里要起三个 xorriso 子进程
（末区段门禁探询、尺寸预演、提交），每次都要重新初始化驱动器并读进旧区段的整份
ISO 结构，实测写前 51.0 秒、总计 81.4 秒。同一次真机验证也把原生增长这条路验完
了：写前 0.3 秒、总计 16.9 秒，写入内容读回一致，嫁接的 220 MB 老文件 sha256 与
Release 产物一致（附录见 ADR-0025）。

决定把默认档切到原生，并把原生做不到或没验过的情形按介质事实回退到 xorriso。回退
不是可选项：随机可写介质上原生增长直接拒绝（`GrowthOnRewritable`，ADR-0020 决策 8），
指定倍速时原生没有 SET CD SPEED（`NativeGap::WriteSpeed`），这两类不回退就从“慢”
变成“用不了”。

## 决策

1. `auto` 在 Linux 与 Windows 都是原生增长（`grow_backend_name(Auto)` 两边都报
   `native`）。Windows 上没有能访问光驱的 xorriso，本就没有可回退的对象，行为与
   改动前一致。
2. Linux 的 `auto` 在每次写入前按设备事实解析一次实际后端，回退判据只有三条：
   - 盘片状态位 0b11（随机可写介质，例如 DVD-RAM、BD-RE）。
   - 驱动器报的 Profile 不在原生支持的名单里。
   - 调用方指定了倍速。
   判据只看驱动器的静态事实与调用方的请求，不看写入过程中的报错：写失败时盘上可能
   已经写了一半，自动回退会再写一次，多留一个损坏末区段。
3. 判定只有一份实现：`grow_backend_choice`（引擎）与它的纯函数 `grow_suitability_of`。
   写前门禁的末区段判定、尺寸预演、写入三条入口共用它，因此三者永远看到同一个后端。
   设备事实探不到（打不开、命令失败）时按平台默认走原生，不把分派变成新的故障点。
4. 选择优先级：界面或参数的显式选择 > 环境开关 `OPTIBURN_GROW_BACKEND` > 平台默认。
   显式 `native` 不回退，缺口按 `NativeGap` 原样报错（诊断用）。显式 `xorriso` 在
   Windows 上仍被拒。
5. GUI 追加页加“增长模式后端”选择（跟随默认 / 原生增长 / xorriso 增长模式）。回退
   发生时把原因写进结果消息，CLI 在 stdout 打一行，用户能立刻知道为什么这次慢了。
6. 镜像刻录（`burn`）不动，仍按平台分派。它的写前窗口只有一次 xorriso 调用（没有
   旧区段可读，42 秒的尺寸预演那一步不存在），收益小，而它有自己的写序列要验。
7. 倍速：原生档不接受 `--speed`，`auto` 档下指定倍速即回退 xorriso。实现 SET CD SPEED
   留作后续，切默认不依赖它。

## 接受的风险

- DVD±R、BD-R 的原生写序列（`DvdMinus` 的增量写与 `PlusOrBdR` 的不设写参数页两条
  分支）没有真机证据。平台表与 README 明确标注，遇到问题用显式 `xorriso` 回退。
- 增长区段不带 Rock Ridge（ADR-0020 的写法），xorriso 增长带。Windows 侧读 Joliet
  完全一致，Linux 桌面默认 `norock` 挂载也一致，差别只在显式 `-o rock` 挂载时。
- 写盘质量没有测量手段：原生不参与倍速协商，实测写入耗时在 16.5 到 28.6 秒之间波动
  （同类型小区段），主因未定性。

## 验证

- 离线单测钉住三件事：回退判据（随机可写、未知 Profile、指定倍速三种输入各一条）、
  选择优先级（显式 > 环境 > 平台）、显式选择不回退也不探设备。
- 真机（2026-10-15，多区段 CD-R，HL-DT-ST GP70N，无环境开关）：
  - 默认档走原生：写前 1.5 加 0.1 加 0.0 秒，写入 28.6 秒，合计 30.2 秒（改动前同一
    张盘的默认档是写前 51.0 秒、合计 81.4 秒）。区段 6 的主标识名视图是大写 ECMA
    名，确认是原生写的。
  - 回退判据生效：加 `--speed 8` 后打印“指定了倍速，而原生引擎还没有实现设速，本次
    改用 xorriso 增长模式”，门禁阶段 5.8 秒（原生档同一步 1.5 秒），实际写入走
    xorriso（区段 7 的主标识名视图是 libisofs 替代名）。

## 被否决的方案

- 原生写失败后自动回退 xorriso 重试：失败时盘上可能已经写了一半，重试只会多留一个
  损坏末区段，代价远大于省下的一次操作。
- 只切 CD 族、DVD/BD 等有介质再切：用户明确要求全切。介质缺口改用文档标注与显式回退承担。
- 先实现 SET CD SPEED 再切：把默认档的收益再押后一轮，而倍速回退判据已经让
  `--speed` 这条路保持可用。

## 后果

- Linux 默认档的追加写前从 51.0 秒降到 1.6 秒，写前窗口里不再有子进程。xorriso 只剩三个出口（随机可写介质、未知 Profile、指定倍速），加上显式选择。
- `OPTIBURN_GROW_BACKEND` 从“切到原生”的开关变成“显式选择或回退”的开关，默认档
  不再是它。
- 文档同步：ADR-0019 的预演口径、ADR-0020 决策 9、ADR-0025 的开关语义各加一行指向本 ADR。`docs/ARCHITECTURE.md` 的增长模式分派与平台表、`CONTEXT.md` 的增长模式
  与增长模式后端、两份 README、`CHANGELOG.md`。
