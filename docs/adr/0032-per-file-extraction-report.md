# ADR-0032：读盘抽取的逐项报告

- 状态：已接受
- 日期：2026-10-18

## 背景

issue #53 的现场：一张盘上有两个文件读不出来。整树抽取（`extract_tree`）在第一个读
失败处整体返回错误，跑了 323 秒后只给一句 `disc read failed`。中途抽出的文件留在目标
目录里，调用方无法知道哪些文件完整、哪些没读出来。同一张盘改用按路径抽取、每次只请求
一个文件，36 个文件里 34 个正常、2 个报错，逐个好辨。信息在下层是有的，只是整树抽取
把它压成了一个错误。

同一个缺口的另一面是 #51：抢救探测阶段的失败被报成整体失败。抢救路径已经按写入边界
给每个文件定性（完整、半截、一个字节都没写），读盘抽取缺的是同一类逐项结论。

## 决策

1. `extract_tree` 与 `extract_paths` 的公开函数、`ReadBackend` trait 的两个同名方法
   都改为 `Result<ExtractReport, BurnError>`，不留旧签名的兼容入口。仓库约定改接口就
   迁移全部调用方，现有调用方只有 GUI 的复制与校验，CLI 没有抽取命令。
2. 报告形状与 `SalvageReport` 同构：`ExtractReport { files }`、`ExtractedFile { path,
   size, state }`、`ExtractState::{Complete, Unreadable { reason }}`。path 用盘上路径，
   前导斜杠、`/` 分隔。size 取盘上目录记录，读不出的文件也保留。reason 是下层错误的
   文案，只作展示与诊断，类型化错误仍由 `BurnError` 承担。
3. 只做完整与读不出两态。现有实现把文件整份读入内存后一次落盘，读失败的文件不会留下
   半截，Truncated 在结构上不会出现。要支持半截必须改成分块读取与部分落盘，那是另一
   个改动，不在本 ADR 的范围。
4. 错误边界：单个文件的数据读失败、按路径请求找不到，记 `Unreadable` 后继续。目录读
   失败、打不开设备、没有可用的 ISO 9660 区段、空白盘、取消、不安全路径、本地写失败
   仍整次返回 `Err`。取消在记录读不出之前判断，不能把用户中止记成某个文件坏了。
5. 后端边界：逐项状态只有原生读侧能给出。xorriso 只拿进程退出码与 stderr，成功后按
   `dest` 里落盘的文件生成全为完整的报告，失败时照旧返回 `Err` 并触发后端回退。显式
   选择 xorriso 时拿不到逐项报告，这是文档化边界。组合后端的回退条件不变，只在 `Err`
   上触发，部分失败表达成 `Ok(report)` 因此不会触发回退。
6. GUI 语义：离盘复制在部分读不出时保留完整文件并放进剪贴板，结果文案列出读不出的
   路径；只要有读不出的文件，复制任务就按失败收尾（与校验同一口径：两类都为空才算
   通过），一个完整文件都没有时直接报错。回读校验把读不出的盘上文件从参照树里移除后
   再对比，避免被算成盘上缺少文件，结果里把读不出的文件与内容差异分开报。读不出清单
   只统计参照树里也存在的文件，盘上多出的旧文件读不出不算本次校验失败。刻录校验的
   镜像抽取出现读不出时参照树不完整，直接报错，不进入对比。
7. CONTEXT.md 补“抽取报告”术语。ADR-0018 与 ADR-0024 的后果节加指针。

## 后果

- 一张有坏文件的盘上，整树抽取返回 `Ok(report)`，坏文件之后仍会被处理，调用方能逐项
  告诉用户哪些文件完整。
- Linux 默认档（`auto`，xorriso 优先）遇到坏文件时 xorriso 先整体失败并回退原生，原生
  再逐项抽取，整次操作会读两遍盘。这是 ADR-0024 回退语义的既有代价，不是本 ADR 引入。
- 显式 `OPTIBURN_READ_BACKEND=xorriso` 的档位读坏盘仍是整体失败，错误文案与改动前一致。
- 回读校验在盘上有坏文件时报“读不出”而不是“盘上缺少文件”，两类结论可以分别处理。
- 新增测试用按 LBA 失败的块源覆盖 ISO 与 UDF 两套解析，断言坏文件之后仍有文件被抽出。

## 被否决的方案

- 保留旧返回类型，另加一个返回报告的入口：两条路径都要维护，调用方按需选，长期会分叉。
- xorriso 逐文件调用以归因：与 ADR-0012 否决逐文件调用 xorriso 的记录冲突，多文件时
  反复加载盘片。
- 用解析 xorriso stderr 的方式猜哪个文件失败：没有先例与证据，失败文案也不稳定。
- 本轮一并做 Truncated 与分块读取：范围扩到 ISO 与 UDF 的读取层，且 xorriso 后端给不出。
- 本轮一并做坏块重试：重试策略与报告形状正交，偶发率需要真机数据，拆到 #59。
- 单个文件读失败仍整体返回 `Err`，只把原因写细：这正是 issue 要修的问题，调用方拿不到
  部分结果。

本 ADR 与 ADR-0024 被否决的“为一条诊断改读侧返回类型”不冲突。那一条说的是后端回退
这一条诊断信息，本 ADR 改的是用户可见的部分失败结果，两者不是同一类信息。
