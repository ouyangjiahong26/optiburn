# ADR-0012：设备页浏览盘上内容与复制到系统剪贴板

- 状态：已接受
- 日期：2026-10-09

## 背景

实机反馈：查看盘上已有的文件是最常用的操作，但 GUI 此前没有浏览入口。用户还要求
能在设备页点开一张盘看到文件清单，用拖动框选与多选的方式选文件，复制之后可以直接
在系统文件管理器里粘贴。

## 决策

1. 浏览：设备页点击设备卡片展开该盘的目录树（名称、大小、目录标记）。数据来自
   `xorriso -indev <设备> -find / -exec lsdl --`，解析得到路径与大小。用
   `-drive_access shared` 只读打开，本机已挂载的盘也有机会直接读到。读取失败且
   盘处于挂载状态时，文案给出卸载指引。
2. 选取：清单支持单击选中、按住指针拖动框选、Ctrl 加选、Shift 连选。目录不可选，
   选择状态只存在界面里。
3. 复制到剪贴板：点“复制选中文件”先把选中内容从盘上抽到本地暂存目录（一次
   xorriso 调用执行多条 `-extract`，避免逐文件重复读取盘片），再把暂存文件的 URI
   放进系统剪贴板。Linux 用 GTK3 剪贴板，同时提供 `text/uri-list` 与
   `x-special/gnome-copied-files` 两个目标，与 GNOME 的“复制文件”语义一致。
   文件管理器粘贴时按 URI 从暂存目录复制数据。
4. 暂存生命周期：每次复制使用新的序号目录，剪贴板切换成功后清掉更早的暂存，失败
   只清本次目录。剪贴板在应用存活期间有效（GNOME 默认没有常驻剪贴板管理器），
   应用退出后暂存留在系统临时目录由系统回收。

## 被否决的方案

- 浏览用挂载视图（直接读挂载点目录）：多区段盘在 Linux 的挂载视图不完整，还受
  自动挂载与内核容量问题影响。
- 逐个文件调用 xorriso 抽取：每个文件都要重新读取盘片元数据，多文件时不可接受。
- 剪贴板只写路径文本：文件管理器会当文本粘贴，不是文件。
- Windows 剪贴板实现：本轮不做，命令在非 Linux 平台返回明确错误，等有真机再补。

## 后果

- src-tauri 增加 Linux 专属的 gtk 依赖（版本与 tauri 用的 0.18 对齐），只为剪贴板。
- 展开清单是一次盘片元数据读取，大目录一次列全，界面按固定高度滚动。
- 每次复制占用与所选文件等量的临时空间，直到下一次复制或应用退出。
- 复制占 GUI 任务槽，与写盘互斥：不会边写边读同一台光驱，任务栏可中止，退出确认
  会等它收尾。
- 剪贴板是 GUI 层的平台能力差异，收在 `src-tauri/src/clipboard.rs` 的平台模块里。
  `optiburn-transport` 只收硬件层差异，两类不混。
- 暂存目录用带时间戳的唯一名字创建（`create_dir`，不跟随预置的同名符号链接），
  崩溃残留留在系统临时目录等回收。
- 实测范围是 Linux 桌面。已挂载盘的 shared 读取与 Windows 行为待后续验证。

## 补记：读侧后端化与 Windows 可用（2026-10-10，ADR-0018）

本文的浏览与复制当时只有 xorriso 一条实现。读侧现在接在 `ReadBackend` 接缝上
（xorriso 子进程与原生 MMC 解析两个后端，Windows 默认原生），GUI 的命令层不变。
Windows 上“展开盘上清单”与“复制选中文件”随原生读盘一并可用。复制到剪贴板的
Windows 实现仍按本文决策不做，命令在非 Linux 平台依旧返回明确错误。
